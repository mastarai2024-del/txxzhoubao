# 报告格式

用户现有格式优先，包括用户改过的标题。没有可用格式时采用以下字段，顺序保持一致：

| 字段 | 写法 |
|---|---|
| 模块标题 | 加粗，用项目或方向命名，大事项单独成块 |
| 事项 | 一句话说明本期在做什么 |
| 目标 | 已确认的本期目标与交付物，期限有依据再写 |
| 进展 | 通常3–5条，每条约30字；用动词开头，只写有证据的结论和动作 |
| 风险 | 写具体阻塞及影响；未覆盖来源不能据此断言“无风险” |
| 需要的资源 | 已确认需要谁配合什么，没有则留空 |
| 下周计划 | 通常2–3条，回应本期进展；建议须明确标注，日期不能补造 |

条数服从证据，不凑数。月报最后一项按现有格式改为下月计划。模块用既有分隔方式，默认 Markdown 分隔线；写入飞书时采用工具支持的原生结构。

表达示例均为虚构写法，不可当作本期素材：

- “明确升级失败重试规则，补齐需求验收条件。”是文档成果，不改写成“升级功能上线”。
- “核对支付异常，当前仍待研发处理。”保留状态，不改写成“解决支付异常”。
- 会议只写有本人关联的结论；“参加需求会”本身不足以说明工作进展。

提交前检查：格式与上期一致、回应上期计划、本人关联明确、本期日期正确、状态未夸大、无重复或空话、计划和风险均有依据。来源明细和读取缺口放在草稿外的说明中，保留给用户核对。
