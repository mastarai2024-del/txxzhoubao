# 信息源验收

每次写报告先定义日期与时区；每一行独立验收，一路成功不代表其余来源通过。

| 来源 | 获取内容 | 完成标准 |
|---|---|---|
| 上期周报 | 本人单元格、模块、计划及风险 | 已读全本人上期内容并能逐项回应；本期已有编辑另行保留 |
| 文档/知识库 | 本期编写或评审的需求、方案、设计说明 | 读取正文，核对版本、日期和本人关联，保留原链接 |
| 群聊 | 本人发言、被提及及相关线程 | 覆盖范围内分页完成，核对决定、责任与后续，不重复计数 |
| 会议 | 实际参会、讨论结论、本人行动项 | 纪要/原文与参会或行动项支持本人关联；日程标题不足以证明 |
| 飞书项目 | 本人相关需求/缺陷及本期变化 | 直接读取详情、状态、优先级、角色和时间；迁移结论有操作记录依据 |
| 日历 | 本期会议和时间块 | 指定范围实际读取，补齐会议线索，不推定出席和产出 |

会议文档、妙记搜索、妙记摘要和逐字稿可受不同权限限制，分别记录。每项状态用“实际通过 / 成功无结果 / 待审批 / 缺权限 / 工具缺失 / 查询失败”；访问条件满足但尚未实测时写“待验证”。

最小素材记录：事项、来源 URL 或对象 ID、日期、本人关系、动作/结论、当前状态、限制。原始业务材料保存在本次约定的本机工作目录，不作为技能或仓库资产。临时依赖与输出放项目已忽略目录或系统临时目录。

先读上期，再收集会议、消息、项目和文档，最后用日历查漏；独立只读请求可批量执行。同一事项跨来源合并，冲突先核对时间和正式结构化字段，无法确定的保留待确认。

正式草稿交付前说明哪些来源完整读取、哪些仅抽样、哪些无法读取。已有周报回读只能证明格式和历史内容可用，不能算从全部原始来源重建通过。
